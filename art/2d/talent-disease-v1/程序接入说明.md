# 程序接入说明

用户要求美术完成后通知当前项目的“程序员”，由其完成天赋选择代码。本批20个图标已完成，透明通道、来源、互斥索引和浏览器预览检查通过。本批只新增美术与导入数据、预览，没有修改游戏运行代码；请继续实现游戏内选择、结算与存档流程。

入口读取 manifest.json 或 game-art.js：按 gameId 找图标，不用中文名称当存档主键。T01—T10为天赋、D01—D10为疾病，PNG单张单项，无需图集切帧。每个图标的PNG、提示词和来源记录可对应检查。

1. 模式与名字 → 天赋/疾病 → 属性预览 → 确认开始。上一步返回保留草稿，未确认不启动游戏计时、不覆盖旧存档；0/0默认合法并提供“无天赋开始”。
2. 最多2项天赋；确认只接受0/0、1/1、2/2。每项不可重复，允许选择过程中临时数量不等，不自动替换或删除选择。
3. 互斥检查针对整组选择，而非两个槽位。同属性的10对双向禁止，其余组合按规则允许；不是每个天赋必须选择表中同一行疾病。点击互斥项显示具体已选项名称与原因。
4. 每卡显示名称、明确增减数值、当前状态和互斥原因；近视必须写明“地面白天改为18米”，不模糊文字/UI。已选边框、勾选、互斥叉号、数量上限状态由界面叠加，保留图标本身的清晰度。
5. 属性预览至少显示生命/体力上限、恢复等待/间隔、步行/奔跑、个人视距和自然饱食消耗；动作、伤害、治疗显示在卡片和摘要中。图标不暗示额外技能，也不扩大照明半径。
6. 使用基础属性+本局特征+当前效果推导最终属性。v1旧饱食示例不可覆盖当前正在更新的60/30/0分档与恢复、饥饿扣血规则；请将特征增减/倍率叠加到最新基准，若文档尚未同步，以最新直接用户要求为准。
7. frail_constitution是疾病虚弱，不是临时roar_weakness；康复只乘生命恢复量，明察/近视不改灯具真实光区，代谢只改自然消耗，迅捷/腿疾不改玩家潜伏技能固定速度。其余作用范围按原规则。
8. 开始后在角色详情持续显示已选图标和效果。保存模式、名称和稳定ID；继续存档直接恢复。旧存档缺字段按两个空列表处理；载入不能再次加血量或重复乘倍率；普通菜单不提供清除疾病白拿天赋的入口。

完整效果与数值以项目根目录《开局天赋与疾病规则.md》和最新用户规则为准。请保留现有工作区改动，在当前已授权工作基础上接入本功能，遵守该任务现有验证/部署限制，自动检测保持关闭。美术预览检查不等于游戏选择流程与数值验收。
